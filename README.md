# PainelCli

PainelCli is an experimental native macOS AppKit app that discovers Codex CLI, Claude Code, Gemini CLI, and Antigravity CLI while keeping a separate list of manual registrations. Discovery checks executable files in the running app's `PATH`, common macOS/user locations, the ChatGPT-bundled Codex path, and legacy PainelCli-managed paths. Antigravity uses the official `agy` executable; Gemini CLI remains a distinct detection target and is never relabeled as Antigravity. Discovery never runs a CLI or authenticates and is not a universal inventory.

The compact list has two groups: **Instalações detectadas** displays unnumbered installation names, with visible but disabled account and trash controls and no active delete or hide actions; **Cadastros manuais** displays per-provider numbered registrations with scoped actions. Manual ordinals start at zero independently for each provider, and new registrations take the smallest unused ordinal. Automatic rows follow the current filesystem inventory and have stable identities per target/discovery path; they never occupy manual ordinals. Adding a catalog entry always creates a manual registration, even when an installation of the same provider is already visible. Removing an installed Codex or Claude manual registration deletes that UUID's managed package and local data before removing its row; the app confirms this irreversible action. Claude Desinstalar first runs and verifies official logout, then records a private UUID cleanup receipt before removing the package; the subsequent trash can remove the receipt, config, and row without reinstalling. If logout or receipt persistence fails, the package and row remain. Other manual rows remove metadata only. Legacy automatic registrations and hidden-discovery metadata are migrated by the store snapshot API. Manual IDs are preserved; legacy manual ordinals are compacted once per provider in their previous ordinal order.

The manual-registration catalog is exactly CodexCLI, ClaudeCLI, and Antigravity CLI. Selecting a catalog item records metadata; all three can install their own managed package per UUID. Codex uses a UUID-scoped package directory, `CODEX_HOME`, and credential file. Claude uses `CLAUDE_CONFIG_DIR`, a private HOME/XDG/temp tree, and the official CLI's directory-scoped macOS Keychain behavior. Its status is accepted only when `claude auth status --json` reports `authMethod: "claude.ai"` for that UUID's config directory. Antigravity installation stages the official architecture-specific `agy` binary under the UUID after checking the release manifest's SHA-512; its private HOME/XDG/temp paths are ready for a future runtime. The Antigravity account action is disabled, and this version does not query, create, or remove its login. Google documents that Antigravity CLI and app share system-keyring credentials, so UUID-local directories cannot isolate that account store; see [the Antigravity isolation contract](docs/antigravity-isolation-contract.md). Legacy GeminiCLI registrations migrate to Antigravity only when no real Gemini executable is detected and the migrated ordinal does not collide; otherwise they remain intact and the app asks for an explicit decision.

**Status: development. No production version has been approved.** Version 0.0.0.35 is the current development baseline. The `develop` branch contains the app; `main` contains production policy and remains without an approved app release. A production promotion requires passing technical checks and the project owner's explicit functional acceptance. Promotion happens through a pull request; CI does not tag, publish, or deploy a release.

## Build and test

Requirements: macOS, Xcode Command Line Tools, Swift, Python 3, and Go 1.26 or newer for the bundled CLIProxy engine. Run `scripts/build-cliproxy-engine.sh` to fetch the pinned CLIProxyAPI source, apply the local loopback callback patch, build the app-managed engine, and write its digest/license files under `Resources/`. This script uses the selected Go toolchain and does not install one. Then run `python3 scripts/build-open.py` to compile the app, keep the current and previous local bundles, and open the app. Run `scripts/ci-check.sh` to compile the AppKit executable and run the isolated store/installer test suite without opening the app. GitHub Actions runs the same check on macOS for pushes and pull requests to `main` and `develop`; it does not launch or authenticate CLIProxyAPI.

The test suite uses temporary synthetic files and injected npm/CLI/network runners to verify per-registration paths, auth-status parsing, logout confirmation, per-UUID cleanup, concurrency, and failure handling. It never runs a real CLI, npm installer, Keychain operation, login flow, or network artifact download.

## CLI installation limits

The **Configurações → CLIProxy** screen has a separate profile collection; it does not read, display, or reuse native CLI registrations or credentials. Codex and Claude profiles each get their own UUID, configuration, auth directory, process, and login flow. The engine binary is shared and immutable, built from CLIProxyAPI v8.0.16 commit `a2976eb8a303f11b4ea5177bce9f9ff752634dfc` with [the local callback-binding patch](Resources/CLIProxyAPI-loopback.patch); its OAuth callback listeners bind only to verified loopback addresses while preserving the upstream localhost redirect and OAuth flow. The app does not present this local adaptation as an OpenAI- or Anthropic-approved integration. Antigravity is listed as unavailable. Profile status distinguishes an active proxy process from provider credentials saved in that profile; the app makes no model request as a health check. Removing a profile requires confirmation, stops only its verified process, and deletes only its UUID directory. A saved provider session is not remotely revoked. Synthetic tests do not verify real browser authorization, provider accounts, or inference; João must test those flows manually.

Codex installation uses the official `@openai/codex` npm package in a local prefix under a directory keyed by registration UUID. Each install receives a private child `HOME`, `CODEX_HOME`, npm cache and npm config files; the Codex home selects `cli_auth_credentials_store = "file"`, which stores auth under that instance's `CODEX_HOME/auth.json`. PainelCli never changes the host's `HOME`, `CODEX_HOME`, `~/.codex`, npm config, or credentials. Installation runs asynchronously, uses a fixed argument list and an isolated staging directory, and is reported successful only after the executable and UUID-bound manifest validate.

Claude installation uses the official `@anthropic-ai/claude-code` npm package from npmjs.org in a local prefix under the registration UUID, with Node.js 22+ and npm supplied by the user. Each install has a private child `HOME`, `CLAUDE_CONFIG_DIR`, XDG paths, temporary directory and npm cache/config. The CLI version is recorded and must support the documented JSON auth status command. The environment removes inherited API keys/OAuth tokens, disables CLI self-updates, and never invokes the detected global `claude` executable. Anthropic documents that macOS Keychain entries and fallback credential files follow `CLAUDE_CONFIG_DIR`; it separately documents legacy Console login caveats. The app accepts only `claude.ai` subscription auth and leaves API-key, OAuth-token, helper and third-party modes indeterminate. Details and exact links are in [the Claude isolation contract](docs/claude-code-isolation-contract.md).

The separate Desinstalar action removes the managed package and manifest for that UUID, retaining configuration, history, and caches for reinstall. For Claude it first runs `claude auth logout` with that UUID's `CLAUDE_CONFIG_DIR`, confirms the same config directory reports `authMethod: none`, writes a private receipt bound to the UUID/config path, and only then removes the package. The confirmation explains that local login is ended and must be repeated after reinstall. If logout, status verification, or receipt writing fails, the package and registration stay available. Trash after successful Claude uninstall validates the receipt before deleting its UUID directory and row, so it does not require a reinstall; a package removed outside PainelCli without a valid receipt cannot prove cleanup and is blocked. The official authentication guide documents the Keychain entry's config-directory scope and the CLI's credential management through login/logout; PainelCli does not inspect Keychain items or secrets. Login/logout are user-triggered; startup only asks the isolated CLI for its read-only status. Synthetic tests do not establish real browser, Keychain, account, or model behavior. João must test those flows manually. The current CLI receives a per-process Safari `BROWSER` hint without changing the macOS default, but Anthropic does not document that variable; Safari opening remains a user retest criterion. Logout may invalidate a provider credential, and the app does not promise to revoke all remote sessions.

Antigravity's **Desinstalar** removes only the UUID-owned binary and install manifest; its private settings and runtime directories remain available for reinstall. Trash removes that UUID's tree and row. Neither action invokes the Antigravity CLI, logout, account status, browser, or global installation. The installer follows Google's current official release manifest URL and artifact path, verifies the published SHA-512 before extraction, and stages only the `antigravity` executable. See [the Antigravity isolation contract](docs/antigravity-isolation-contract.md) for the shared-keyring and future runtime limits.

The catalog no longer creates GeminiCLI registrations. Existing GeminiCLI registration metadata is migrated only under the safe conditions described above; the app does not read, copy, or alter Gemini or Antigravity credentials/configuration. Codex installation and its per-registration file credential setting follow the [Codex CLI quickstart](https://developers.openai.com/codex/cli) and [configuration reference](https://developers.openai.com/codex/config-reference#cli_auth_credentials_store).

## Detected-row presentation

Detected installations display only their unnumbered name, centered vertically, with no status subtitle. Discovery details remain available as a tooltip and accessibility help. Each detected target uses a distinct native SF Symbol: Codex — `chevron.left.forwardslash.chevron.right` (blue); Claude — `text.bubble` (orange); Gemini CLI — `sparkles` (purple); Antigravity CLI — `arrow.up.circle` (teal). These are system-provided identification cues, not official provider logos. No third-party brand asset is bundled or distributed. Source: https://developer.apple.com/sf-symbols/ . Account controls are disabled for all rows; automatic trash controls are disabled; manual registrations remain removable.

Disabled account/install/trash controls use the semantic macOS disabled-control gray; manual removal remains enabled.

Rows show two native symbols: CLI identity followed by origin (`desktopcomputer` for external discoveries; `app` for managed installations or manual registrations). Tooltips distinguish a manual registration from its UUID-scoped installation status. Installation is never inferred from a provider-wide discovery; login is not inferred from an install.

## Compact action presentation

All row actions are icon-only with 28 × 28 pt controls and the same native 14 pt symbol configuration. Download (`arrow.down.circle`) installs; package (`shippingbox`) uninstalls while preserving registration data; person (`person.crop.circle`) starts login; power (`power`) logs out; cancel (`xmark.circle`) cancels a running login; trash definitively removes an eligible manual registration and its UUID-local files after confirmation. Tooltips and accessibility names identify each action. Enabled login is green, logout/cancel/uninstall orange, remove red; disabled actions use native semantic gray. These colors and symbols do not determine action availability. UUID-scoped handlers and uncertain-state guards remain the source of behavior. No Code/device/clipboard action is present.

While the existing per-registration package operation state is `installing`, the static package-action icon is hidden and a native indeterminate spinner occupies the same 28 pt action slot. This is visual feedback only: no percentage or estimated duration is fabricated, and the existing operation locks, handlers and final-state validation are unchanged. The spinner also covers uninstall because the backend uses the same package-operation state.

### CLIProxy visual pattern

The CLIProxy screen reuses native provider symbols, compact 56 pt profile rows, subtle separators, 28 pt icon-only actions, explicit tooltips/accessibility labels, and the existing top-right + control. Codex/Claude have independent profile add actions; Antigravity remains visibly unavailable with a disabled lock icon. Process health and provider-account state retain their separate core meanings. No native CLI list or credential reuse is introduced by the presentation. Profile operations show a native spinner only in the existing busy state.
